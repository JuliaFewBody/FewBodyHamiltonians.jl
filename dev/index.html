FewBodyHamiltonians.jl

Documentation for FewBodyHamiltonians.jl.

Construct once, solve with a backend

using FewBodyHamiltonians
H = Kinetic([1.0e15, 1.0, 1.0]) + Coulomb([2, -1, -1])
validate(H)
Hamiltonian (3 particles; Ha, bohr):
  Kinetic(masses = [1.0e15, 1.0, 1.0])
  - 2.0 Coulomb(1, 2)
  - 2.0 Coulomb(1, 3)
  + 1.0 Coulomb(2, 3)

Kinetic(masses) fixes the particle ordering and removes center-of-mass motion in each backend. Add pair terms using the same indices:

V = -10 * Gaussian(1, 2; exponent = 0.5) + 0.25 * Oscillator(2, 3)
H2 = Kinetic([2.0, 1.0, 1.0]) + V
threebody = Gaussian(1, 2; exponent = 0.5) * Gaussian(2, 3; exponent = 0.5)
validate(H2 + threebody)
Hamiltonian (3 particles; Ha, bohr):
  Kinetic(masses = [2.0, 1.0, 1.0])
  - 10.0 Gaussian(1, 2; exponent = 0.5)
  + 0.25 Oscillator(2, 3)
  + 1.0 Gaussian(1, 2; exponent = 0.5) * Gaussian(2, 3; exponent = 0.5)

Unit labels do not convert values. The kinetic convention is ℏ=1, so nuclear masses are expressed as mc²/(ℏc)² when using MeV and fm. Coulomb(charges) assumes atomic Coulomb couplings; for other units, write explicit pair coefficients in those units.

Backend capabilities

These integrations require consumer versions depending on FewBodyHamiltonians 0.1; earlier releases may still define separate construction types.

BackendShared terms supported
FewBodyECGAll construction terms; spin terms require its spin-dependent matrix layer
FewBodyVMCAtomic-unit Kinetic and Coulomb
TwoBodyTwo-particle Kinetic, Coulomb, Gaussian, ManyBodyGaussian, Oscillator, Custom

Each backend validates its numerical restrictions. Custom quadrature options are hints honored by FewBodyECG; TwoBody uses its backend quadrature settings, and VMC does not support Custom. FewBody re-exports construction without providing an umbrella solver. Use qualified solver names when importing several backends together.

Legacy particle terms

Kinetic(n, ℏ, m) remains available as a compatibility constructor returning ParticleKinetic. Its single-particle meaning differs from Kinetic(masses); full-system backends do not guess missing masses or remove center-of-mass motion from legacy input. Coulomb(i, j, coefficient) and Hamiltonian(terms...) remain available, with the same pair coefficients and insertion order.

FewBodyHamiltonians.Coulomb — Type
Coulomb(i, j; coefficient = 1)
Coulomb(charges)

Coulomb pair potential coefficient / rᵢⱼ between particles i and j.

Coulomb(charges) is the sum over all pairs i < j of Coulomb(i, j; coefficient = charges[i] * charges[j]), ordered (1,2), (1,3), …, (2,3), …. The coupling qᵢqⱼ assumes atomic units ($e^2/4\pi\varepsilon_0 = 1$), so it can only be solved with a Kinetic in atomic units.

source
FewBodyHamiltonians.Custom — Type
Custom(f, i, j; rtol = 1e-8, atol = 0.0, maxevals = 10_000)

Pair potential f(rᵢⱼ) given by a callable of the distance. Its matrix elements may be computed by adaptive radial quadrature. The tolerances are backend hints: FewBodyECG honors them, while other solvers may use their own quadrature settings. A scalar multiplier is kept as the term's coefficient, so c * Custom(f, i, j) is the potential c · f(rᵢⱼ).

FewBodyHamiltonians.Gaussian — Type
Gaussian(i, j; coefficient = 1, exponent)

Gaussian pair potential coefficient · exp(-exponent · rᵢⱼ²). exponent has no default.

The product of Gaussian terms is a Gaussian in several pair distances, coefficient · exp(-Σₖ exponentₖ rₖ²), which writes many-body forces:

W₃ * Gaussian(1, 2; exponent = γ) * Gaussian(1, 3; exponent = γ) * Gaussian(2, 3; exponent = γ)

FewBodyHamiltonians.Hamiltonian — Type
Hamiltonian

A sum of physical terms (Kinetic, Coulomb, Gaussian, …), built with +, -, scalar * and /, and sum:

q = [+2, -1, -1]
H = Kinetic([1.0e15, 1.0, 1.0]) +
    sum(Coulomb(i, j; coefficient = q[i] * q[j]) for i in 1:3 for j in (i + 1):3)

The terms are kept in the order they were written; like terms are not merged. A Hamiltonian passed to solve must contain exactly one Kinetic term; partial sums without one are ordinary values.

source
FewBodyHamiltonians.Kinetic — Type
Kinetic(masses; units = :atomic)

Kinetic energy $-\sum_i \nabla_i^2 / 2m_i$ of all particles, with the center-of-mass motion removed ($\hbar = 1$).

masses defines the system: its length is the number of particles, and its order fixes the particle indices used by every other term. units is :atomic, :nuclear, or a UnitSystem; it names the units of the masses and couplings and labels the results, and converts nothing. A Hamiltonian holds exactly one Kinetic term.

H = Kinetic([1.0e15, 1.0, 1.0]) + Coulomb([+2, -1, -1])   # helium

FewBodyHamiltonians.ManyBodyGaussian — Type
ManyBodyGaussian(G; coefficient = 1)

Many-body Gaussian coefficient · exp(-xᵀ G x), where x stacks the particle positions and G is a symmetric N × N matrix with zero row sums, so the potential depends only on relative positions. A pair Gaussian has G = exponent · eᵢⱼeᵢⱼᵀ with eᵢⱼ = eᵢ - eⱼ; products of Gaussians add their G matrices.

FewBodyHamiltonians.ParticleKinetic — Type
ParticleKinetic(n, ℏ, m)

Legacy single-particle term -ℏ²∇ₙ²/(2m), also constructed by the pre-0.1 signature Kinetic(n, ℏ, m). It is not a full-system Kinetic(masses) and is not implicitly interpreted as a center-of-mass-free or reduced-mass operator.

FewBodyHamiltonians.SpinOrbit — Type
SpinOrbit(i, j; coefficient = 1, exponent)

Gaussian-form spin-orbit interaction between particles i and j, coupling the orbital motion in their pair coordinate (range exponent) to their total spin. This requires a backend with spin-dependent matrix elements, such as FewBodyECG with a SpinGaussian basis.

FewBodyHamiltonians.Tensor — Type
Tensor(i, j; coefficient = 1, exponent, traceless = true)

Gaussian-form tensor interaction between particles i and j, coupling their pair coordinate (range exponent) to their spins. This requires a backend with spin-dependent matrix elements, such as FewBodyECG with a SpinGaussian basis.

FewBodyHamiltonians.UnitSystem — Type
UnitSystem(energy, length)

Names of the energy and length units in which a system's masses and coupling constants are expressed. The shared construction API never converts between unit systems: the kinetic operator is $-\sum_i \nabla_i^2 / 2m_i$ ($\hbar = 1$), so the masses and potential parameters of a Hamiltonian fix the units, and a UnitSystem only labels results (printed energies, plot axes).

Presets, selected with Kinetic(masses; units = name):

nameenergylengthmasses
:atomic (default)Habohrmultiples of the electron mass
:nuclearMeVfm$mc^2 / (\hbar c)^2$ in MeV⁻¹ fm⁻², with $\hbar c = 197.327$ MeV fm

For any other convention, pass a UnitSystem directly, e.g. UnitSystem("GeV", "GeV⁻¹") for $\hbar = c = 1$ with masses in GeV.

FewBodyHamiltonians.validate — Method
validate(H::Hamiltonian) -> H

Check that a full-system Hamiltonian has exactly one Kinetic(masses) and consistent particle indices, Gaussian matrix dimensions and charge shorthand. Coulomb(charges) assumes atomic units; explicit pair couplings work with any unit labels. Backends separately check which operator types they support.
